# 美术方案 v4 —— AI 生成为主力的分层路线（试点闸门制）

> 2026-09-10 立项。前置结论：v1 像素（观感差/密度低）→ v2 LuizMelo+Admurin 混搭（三方风格参差）→ v3 程序化 SDF 卡通（不够精美）三连否决。
> 本文回答一个问题：**美术从哪来，花多少钱，怎么保证"统一 + 精美"。**

---

## 0. 需求定义（从三连否决推出的硬约束）

| 约束 | 结论 |
|---|---|
| 风格统一 | 22 物种 + 英雄 + 特效 + 瓦片 + 图标必须出自**同一风格体系**（混搭已被 v2 否决） |
| 精美 | 单体质量要过"商业手游"心理线，程序化生成（v3）上限不够 |
| 覆盖面 | 22 物种 × 4 动画（idle/walk/attack/die，idle 必备余可回退）+ 英雄 4 动画 + 3 特效 + 36 瓦片格 + 19 图标 +（可选）11 地标 |
| 成本 | 个人开发者，先免费验证再花钱，总预算有上限 |
| 工期 | 每周 <10h，全量换装可摊 4-6 周 |

**工程侧已就绪**（v2/v3 两次换装验证过的契约，任何新素材只需满足它）：

- 怪物：每个动画一条**横向条带 PNG**（等宽格、透明背景、角色朝右）→ `tools/slice_spritesheets_v2.gd` 配置一条 → 切帧 → `--import` → `pack` 产出 SpriteFrames → `.tres` 一行 `frames_override` 换源。怪物逻辑/场景/数值**零改动**。
- 瓦片：448×640 / 16px 网格**同坐标换源**（`generate_tiles.gd` 坐标表与 na_tileset 完全一致），色相须落 terrain_painter 的 HSV 色桶。
- 图标：19 枚 64px PNG 直接替换。
- 验收：`--sheet` 样张 + `screenshot.tscn` 实机双帧 + 六项无头测试全绿。
- **美术量杠杆**：22 物种只映射 6 个体型原型（melee_swarm×5 / splitter×3 / charger×4 / ranged×4 / soldier×4 / guardian×2）——只需精修 6 个母体，其余 16 物种用"母体参考图 + 变体派生"批量生成（换色/换件），v3 的 bake 机制现成。

## 1. 四条路线对比结论

### 路线 A：AI 生成（★ 推荐主力）

2026 年的客观现状（社区+评测共识）：

- **强项**：单张静态图（角色立绘/图标/道具/背景/概念图）已达商用质量；
- **弱项**：动画帧一致性（细节漂移/轮廓抖动）、无缝瓦片拼接（模型不懂网格）；
- **关键认知**：统一风格**靠工作流不靠一键**——固定母体参考图 + 提示词模板 + 锁定调色板，从同一底稿生成变体；
- **动画补强两条路**：① 专用精灵动画工具（单图→动画精灵表）；② 视频生成→抽帧（绿幕循环视频→OpenCV 抽帧→HSV 抠图→条带，有成熟开源方案）。

### 路线 B：现成素材包（只能当补充）

v2 调研已证：**"免费+高分辨率+有动画+可商用+覆盖 22 物种"的单一全家桶不存在**；付费包（CraftPix $5-30/包、Admurin $30、itch.io 各作者包）要么静态要么物种不全，混搭=风格参差（v2 已被否）。

- **可用场景**：图标参考、瓦片风格参照、音效（已用 Kenney/NA）。
- **不可用场景**：怪物主力。此路线单独走不通。

## 2. 推荐策略：AI 主力 + 母体派生 + 试点闸门 + 升级梯

```
P0 风格试点（¥0，1-2 晚）
  └─ 免费额度生成红史莱姆 2-3 种风格 → 实机截图对比 → 用户拍板风格 + go/no-go
P1 AI 全量（¥100-300，摊 4-6 周）
  └─ 风格锁定（母体参考图+提示词模板+调色板入档）
  └─ 6 体型母体精修 → 22 物种派生 → 英雄+3 特效 → 19 图标 → 瓦片风格层
  └─ 每物种过同一验收闸门
升级梯（AI 不达标时逐级）：
  L1 动画弱但静态达标 → AI 母体 + Godot Skeleton2D 骨骼动画（¥0）
  L2 要商业级统一     → 半外包英雄+3 Boss+6 母体（¥2000-6000）+ AI 派生
```

**为什么 AI 当主力**：静态质量 2026 年已够商用（立绘/图标直接用）；22 物种的量只有 AI 能在个人预算内覆盖；母体派生机制天然保统一。动画是最薄弱环节，所以 P0 试点专门验证它，不达标就走 L1/L2，不硬撑。

## 3. P0 试点 SOP（¥0）

**目标**：红史莱姆（splitter 原型）4 动画 × 6-8 帧，2-3 种风格，实机对比。

### 3.1 目录契约（已建好）

```
~/hotw-assets/pilot/
  current/slime/     ← ★ 切帧实际读取这里（idle.png/walk.png/attack.png/die.png 横向条带）
  makko/slime/  autosprite/slime/  jimeng/slime/   ← 各工具产物先放这，选定后拷入 current
```

### 3.2 三种风格的生成入口

**风格 1｜手绘Q版卡通（主推）**：即梦文生图出母体立绘 → AutoSprite（或 Makko）单图生成动画精灵表。
**风格 2｜高清卡通像素**：PixelLab（免费 20 积分够试点）文本直出动画精灵表。
**风格 3｜厚涂幻想**：即梦/Liblib 出立绘 → 即梦图生视频（绿幕循环）→ 抽帧脚本。

提示词模板（风格 1 示例，定稿后固化进本文档附录）：

```
[风格描述：cute hand-painted cartoon, clean thick outline, soft shading,
mobile game asset style], red slime monster, side view facing right,
full body, simple readable silhouette, [纯白背景/绿幕 #00FF00],
no text, no watermark, consistent character design
```

### 3.3 接入命令（素材放入 current 后）

```bash
GODOT="$HOME/Library/Application Support/Steam/steamapps/common/Godot Engine/Godot.app/Contents/MacOS/Godot"
"$GODOT" --headless --path Code -s tools/slice_spritesheets_v2.gd slice   # 切帧（会顺带重切 v2 全表，无害）
"$GODOT" --headless --path Code --import
"$GODOT" --headless --path Code -s tools/slice_spritesheets_v2.gd pack   # 产出 slime_pilot/slime_pilot_frames.tres
# 把 data/species/slime.tres 的 ext_resource 路径改为 slime_pilot/slime_pilot_frames.tres（一行）
"$GODOT" --path Code --resolution 1280x720 res://tests/screenshot.tscn   # 实机双帧 → /tmp/hotw_shot{,_b}.png
```

条带规格：单行横向、等宽格、透明背景、朝右。试点配置已写入 `slice_spritesheets_v2.gd`（`slime_pilot` 条目，cell 156×156；若工具产出 128 格改该行即可）。

### 3.4 验收闸门（用户唯一必做项）

三风格实机对比图 → 拍板：① 选哪种风格；② AI 路线 go/no-go；③ 是否升级预算档（→ L2 半外包）。

## 5. 风险与回退

| 风险 | 对策 |
|---|---|
| AI 动画漂移/不一致 | P0 专门验证；不达标走 L1（骨骼）或 L2（外包），不硬撑 |
| 工具付费墙/账号 | 试点全程免费额度；付费升级**每次用户当次确认** |
| 商用授权纠纷 | 选明确授予权益的平台（即梦"归用户"、AutoSprite"yours to ship"、Scenario 同）；Liblib 只用可商用模型；保存提示词与生成记录自证 |
| 海外工具网络/支付 | 试点优先国内（即梦）+ 免费层（AutoSprite/PixelLab/Scenario）；需付费的海外工具仅在用户自愿时开 |
| 第四次返工 | 一切经过 P0 样张闸门；用户只在小节点拍板（风格定稿/母体定稿/逐物种验收） |
| 现有游戏被破坏 | v2/v3 回退位条款不变：任一物种 `.tres` 一行 `frames_override` 改回即回退；美术改动只走表现层契约，六项无头测试守闸 |
