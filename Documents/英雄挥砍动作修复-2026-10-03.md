# 英雄挥砍动作修复（2026-10-03）

本文件描述挥砍部分；后来确认一并交付的盾牌机制另见 `架盾反击机制与验证-2026-10-03.md`。

## 回归原因

方向挥剑改为独立武器后，三段普攻全部播放 `hurt`（Tiny Swords 的 Guard）。原来 Attack1/2 中的头盔转动、盾牌前后移动、蓄势和收势不再出现，身体近乎静止；恒长直剑配细线弧也弱化了原画的挥击感。

## 本次改法

- 普攻恢复四姿身体动作。第一段使用 Attack1 的四个姿势；第二段从既有低手姿蓄力，接 Attack2 的举盾挥击与收勢；第三段使用高位蓄势接举盾挥击，刀光稍厚
- 这是**现有侧视原画的分层与姿势重组**，没有新增上下视角身体素材，也没有旋转整个人来模拟朝向
- 原画的剑/刀光有些像素覆盖在盾和靴子上，不能整块抠掉。避开剑遮盾的 Attack2 前两帧；被剑遮住的低手靴子从 Attack1 完整站脚帧复制。保留来源坐标，三种皮肤使用相同几何，脸、盾、手和脚不靠运行时颜色遮罩裁切
- 剑柄跟随每帧原画手点；独立剑和渐细弧光使用原画色板。66px 是**刀光扫掠外缘**，不是恒长金属剑
- 第二段反向斩，左右翻面同步反向；显示和伤害使用同一条带符号、快速出手后缓收的扫掠曲线

## 保持的战斗边界

- 八方向输入和瞄准、66px 半径、58°基础半角、宽弧升级78°上限
- 0.16秒蓄势，伤害只在0.16–0.26秒扫掠，随后0.06秒收势；没有提前伤害或后摇补伤
- 每刀每目标一次伤害，真实碰撞体检测、墙体视线阻断、最高攻速扫完末端
- 身体/阴影/技能逻辑原点保持固定；握点只跟随表现层手部
- 刀光从逻辑原点逐射线裁墙；偏移后的金属剑另按**实际手点→刀尖**的10px包络扫墙，包含护手宽度及像素吸附余量，避免前摇露剑穿墙
- 冲刺中的既有短窗挥击、暂停、传送、死亡、复活、池化残影清理继续覆盖

没有改动属性、技能伤害、生态/密度、保存格式或发布流程。

## 资源生成与检查

原始 Tiny Swords PNG 与原始切帧资源保持不变。派生资源在 `assets/creatures/frames/warrior_motion/`，包含原样 idle/walk/hurt 和新的身体普攻层。运行时不读回图片、不做颜色抠图。

重切 Tiny Swords 或修改几何后运行：

```bash
"$GODOT" --headless --path Code -s tools/generate_warrior_motion.gd
```

只核验派生资源，**不重写文件**：

```bash
"$GODOT" --headless --path Code -s tools/generate_warrior_motion.gd -- --check
```

该检查逐一比较三皮肤108帧的像素、时长、循环标记、脚点及握点元数据；源画、原始帧表或几何变化后忘记更新派生资源会使 CI 失败。

## 验证范围

- 官方 Godot 4.7 Linux，挥砍阶段回归入口为38组套件，合并盾牌后完整入口与CI共40组
- `hero_slash_motion`：三皮肤×三连段×八方向，逐帧身体/握点；真实命中时相、最高攻速连按、暂停、冲刺命中、传送、死亡复活、池化残影；另对真实墙体逐时相检查实际刀身包络
- `directional_attack`、`weapon_effects`、`actor_alignment`、`animation` 与既有战斗/流程/存档/生态全量回归
- 云端 OpenGL 实际运行前后对照，固定重复输入节奏、3倍视图，并附半速对照；该演示用于观察动作，不代表一级正常开局的攻击频率
- 三皮肤原画/分层像素检查与独立重生成核验

iPhone/Metal 性能、触屏手感与持续发热未验证。未进行签名、合并或 TestFlight 发布。
