# 心之世界完整回归与真实渲染器验证

日期：2026-11-24。基线：`main` 的 `26fc397`（PR #23 合并后）。本机环境：macOS、Apple M4、Steam 版 Godot `4.7.2.stable`、Metal 渲染器——**与 CI 的 Linux + 官方 4.7 不同**，下列结果不替代 CI，也不等于 iPhone 验收。

起因是用户反馈"目前 bug 比较多"。按 `AGENTS.md` 用 Steam 版 Godot 跑完整回归，129 项中 4 项失败；逐项定性后共修复 6 处：游戏缺陷 2 处、装机脚本 1 处、测试基建 3 处。生产代码只改两个文件，共 11 行新增，没有删除行。

## 结论

- 最终工作区的完整无头回归 **129/129 通过**：全部带完成标记、无非预期错误、无超时。
- 用最终代码导出的 PCK，在无头与 Metal 下启动主菜单和世界场景，四条通道均为 0 脚本错误、0 运行期错误、0 运行期警告。
- CI 的 5 组带窗口视觉回归首次在 Metal 上执行，5 组都能通过；其中两组存在低频偶发，原因未查清，见"偶发项"。
- 手势门禁未改动。它带来的"拇指不松开时对话点不动"是有意的新手势契约，取舍留给产品决策。
- 确定性的游戏逻辑缺陷没有发现更多。

## 未改动：新手势契约

排查中发现"屏幕上有另一根手指一直按着时，阅读界面的按钮点不动"。曾把门禁改为只等待落在阅读控件上的旧触点，随后完整回归 129 项中 11 项失败，失败的是同一组断言：

```
FAIL 保留原触点时另一手指不能确认新的线索
FAIL 原触点释放帧不能变成确认
```

这是项目有意的新手势契约（`six_button_hud_test.fresh_gesture_contract` 等）：屏幕上有任何触点按着时出现的新界面，不接受任何确认——另一根手指不行，原触点抬起的那一帧也不行。它由至少四处回归守护：`six_button_hud`、`mobile_clipping`、`outpost_chapter_contract` 及其派生（`campaign_acceptance`、`campaign_complete_story`、`campaign_cross_family`、`campaign_story_lifecycle`、`campaign_lifecycle`、`outpost_chapter_lifecycle`、两个 `*_earned_budget`）。

该修改已全部撤销，四个相关文件恢复为基线。因此下述行为保持不变：左手拇指按着摇杆时打开的对话，拇指不松开就点不动，体感是"第一下没反应"。要给摇杆上的手指开口子，须同步修改上述断言，属产品决策。

## 回归覆盖不到的三类问题

这次两项游戏缺陷都落在无头回归的结构性盲区里：

- 没有窗口，也就没有焦点事件（缺陷 1）。
- 用的是哑元渲染器；真机和 Mac 都是 Metal。
- 跑的是工程目录，而真机跑的是排除 `tests/`、`tools/`，资源带 `.remap` 的导出包。

另外，CI 那 5 组带窗口的视觉回归与 OpenGL 硬绑定（启动参数、通过条件要求日志含 `OpenGL API`、要求有 `DISPLAY`），此前从未在 Metal 上执行过。本次在内存中把这三处替换后执行原脚本，仓库文件未改：

| 组 | 脚本 | Metal 上的结果 |
|---|---|---|
| 战斗阶段与预警提示 | `run_combat_feel_visual.py` | 通过（三种分辨率各 35 个阶段） |
| 装备像素与移动端布局 | `run_equipment_visual_test.py` | 通过（3 次） |
| 地图 | `run_map_performance_visual.py` | 通过 |
| 任务与拾取反馈 | `run_quest_pickup_visual_test.py` | 通过（完整运行 3 次，2 过 1 败） |
| 剧情检查点渲染 | `run_campaign_complete_story_visual.py` | 通过（完整运行 3 次；50 个渲染进程中 1 个在退出阶段报错） |

补充验证的命令已收录在 `AGENTS.md`"无头快速验证"一节。

## 偶发项（未定论）

两项都只在本机带窗口运行时出现，修改前就存在，CI 环境没有报告过：

- **任务与拾取反馈组**：约每 3 次完整运行有 1 次"阅读页点返回后对话状态不对"（`06-wounded-request` 或 `01-chapter-briefing` 处）。可能是测试窗口弹到桌面时收到了真实的鼠标输入，也可能是原门禁在特定时序下的行为。
- **剧情检查点渲染组**：50 个渲染进程中有 1 个在 `get_tree().quit()` **之后**的销毁阶段报 `monster_base.gd:186` 与 `:287`——延迟创建的怪物节点在 `WorldSim.sim` 已清空后才初始化。该进程 87 项断言全部通过，只是日志被判失败，对玩家没有可见影响。

## 验证边界

- 本机是 macOS + Steam 4.7.2 + Metal，不是 CI 的 Linux + 官方 4.7。两个收益预算验收在 4.7.2 上通过，是版本门禁放宽后的结果。
- 两项游戏缺陷的修复效果没有在 iPhone 上确认。
- 视觉回归的 Metal 运行靠运行时替换脚本实现，项目并不正式支持；"偶发项"的两条原因未查清。
- 不包含签名、导出安装或 TestFlight 上传。

## 复现

仓库根目录，`$GODOT` 指向 Steam 版 4.7.2：

```bash
python3 Code/tests/run_headless.py --godot "$GODOT"                                   # 完整 129 项，本机约 90 分钟
python3 Code/tests/run_headless.py --godot "$GODOT" --only mobile_reading_audit       # 定向示例；测试名见 run_headless.py 的 CASES
```

导出包与真实渲染器的三条命令见 `AGENTS.md`。只需 PCK 时用 `--export-pack`，不要用 `--export-debug`：4.7.2 下后者会自己跑 `xcodebuild … archive`，并把中间产物写进真实的 `~/Library/Developer/Xcode/DerivedData/`。
